## Final vision

A desktop application, built in Python with a clean object model, that lets a
small business analyst:

1. Import and clean sales data (CSV first) with clear, line-level diagnostics.
2. See exact business indicators: revenue, cost, gross profit, margin, average
   order value, product rankings.
3. Explore temporal analyses: daily/weekly/monthly revenue and comparisons
   between periods.
4. Visualize indicators and trends in charts.
5. Export PDF reports.
6. Keep companies, catalogs and sales in a local SQLite database.
7. Use everything through a PySide6 graphical interface.
8. Forecast revenue with Machine Learning models that are evaluated
   chronologically against a baseline, with limitations stated to the user.

## Explicitly out of scope

Payments, invoice or tax document issuing (emissão fiscal), inventory/stock
control, payroll and full ERP features. Big-data or cloud technologies (Spark,
NLP, cloud services) are not added unless a concrete requirement appears.

## Incremental roadmap

| Stage | Build | Learning connection / exit condition |
| --- | --- | --- |
| Level 1 — complete | Domain model, CSV import, financial/product analysis, basic daily linear forecast, tests and UML | Assignment model is implemented; video and submission are student actions. |
| Level 2 — current design | In-memory terminal menu over the existing application operations | Implement and test the 27 tasks in `specs/001-terminal-menu/`; no database, charts or GUI in this level. The existing basic forecast is exposed, not replaced. |
| Level 3 — next | SQLite persistence for companies, products and sales; then temporal analyses and period comparisons | Database is required by the assignment. Add charts after Data Visualization units 7–8; add exploratory analysis and hypothesis tests after Data Science units 9–11; PDFs follow stable metrics/charts. |
| Level 4 — later | PySide6/Qt Widgets desktop UI over the same application layer and persisted data | Assignment requires windows, buttons and custom styles. Charts are shown in the GUI but generated by a separate analytics/presentation adapter. |
| Portfolio ML — final expansion | Build on the existing linear forecast with model experiments, feature preparation and honest evaluation | After course units 14–22: classification, regression trees, clustering and stronger time-series evaluation. Keep models outside domain entities and compare to baselines. |

NLP (unit 23), Spark (24–25) and AWS Glue (26) are optional portfolio labs,
not core desktop dependencies for a small local sales application. Revisit them
only if the project gains suitable text data, scale or a concrete cloud pipeline
use case. The current basic revenue forecast is already a small ML component;
“ML at the end” means the broader model family and course projects come after
the core menu, persistence, visualizations and desktop workflow.
